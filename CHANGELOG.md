# Changelog

All notable changes to the Senior Data Scientist AI Guidance artefacts are documented here.

## [0.2.0] - 2026-11-08

### Added
- Created repository-ready `README.md` describing artefact roles, precedence, recommended use, working modes and versioning approach.
- Added initial `data-science-playbook.md`, organised around the analytical lifecycle and professional decision points rather than around languages alone.
- Added practical playbook guidance for problem framing, provenance, SQL/data preparation, EDA, inference, prediction/ML, causal questions, validation, languages, reproducibility, engineering, MLOps, communication, governance, LLM-assisted work and review assurance.

### Changed
- Revised `senior-data-scientist-instructions.md` from v0.1.0 to v0.2.0.
- Strengthened the relationship between instructions and playbook: substantial analysis, design, review and engineering tasks now explicitly consult relevant playbook sections when available.
- Defined how the playbook should be used differently for Review, Design, Engineer and Explain work rather than treating it as passive background.
- Added requirements to explain material departures from playbook guidance and to revisit relevant sections as multi-stage work evolves.
- Kept the core instructions concise enough to remain an operating layer rather than duplicating the playbook.

## [0.1.0-scope] - 2026-11-08

### Added
- Established the complete data-science lifecycle as the organising framework.
- Defined senior practice across problem, analytical, data, computational, validation, engineering, communication and professional judgement.
- Confirmed Python, R and SQL as first-class languages; added Julia, JavaScript/TypeScript and Go in differentiated roles.
- Added explicit LLM-assisted data-science guidance and seven working modes.
- Defined scope boundaries to prevent the guidance becoming an encyclopaedic statistics or software-engineering manual.

### Earlier design decisions incorporated
- Independently compared the initial proposal with suggestions generated by Claude from the same task.
- Adopted evidence-led iteration from observed model failures, task modules, explicit honesty rules, comparative testing and a canonical version-controlled master.
- Modified rather than adopted blanket rules such as "answer/code first", "fail loudly" and random-seed-as-reproducibility.
- Added SQL as a first-class analytical language and clarified computation across SQL, Python and R.
- Deliberately oriented the reusable guidance to a broad audience rather than one user's personal tool preferences.
